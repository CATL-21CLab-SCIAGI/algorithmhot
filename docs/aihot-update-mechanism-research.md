# AIHOT 更新机制与模型配置核对

核对日期：2026-10-06，北京时间。仅研究官方资料及公开接口，未修改 AlgorithmHot 的模型、预算、调度或生产数据。

## 结论

AIHOT 采用持续采集、增量处理和定时成刊。可以称为准实时动态站，但不是上游发布后立即推送的严格实时系统。每天 08:00 的日报是独立产物，日内动态不需要等下一份日报。

模型方面，当前开源模板默认使用 `deepseek-flash`，各处理步骤可以单独配置。没有取得 `aihot.news` 当前生产配置或模型调用回执，因此线上实际模型组合保持 **未确认**，不能把模板默认值或具名示例当作线上事实。

## 与 AlgorithmHot 的机制差异

本次调查时，AlgorithmHot 采用本机批次生成、审计后发布 GitHub Pages 静态快照的方式；AIHOT 使用常驻后端进行增量处理和动态读取。两者的采集、处理、成刊与网页部署节奏应分别核对，不能从网页更新时间推断模型处理覆盖率。AlgorithmHot 的当前运行规则以 README 和 `docs/daily-delivery.md` 为准。

科研试刊使用独立的研究成员与准入记录。跨日结果复用、新内容准入、模型调用预算和日报展示范围需要分别管理；重新发布静态包或更换模型本身不能修复准入逻辑问题。失败或状态未知的请求继续保留原始状态。本文不包含本机运行回执、私有批次统计或模型响应内容。
