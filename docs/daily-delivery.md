# 每日自动产刊与公网更新

## 当前规则（2026-10-09 起）

本机负责采集、研究处理与成刊，GitHub Pages 提供公开阅读快照。日常入口为 Codex heartbeat `algorithmhot`，北京时间每天 **09:00、15:00、21:00** 执行：

```bash
node scripts/daily-delivery.ts --refresh
node scripts/daily-delivery.ts --refresh --status
```

脚本只选择当天最近已到期的 09、15点或21点时段，09 点之前不追跑前一天；重触发复用同一时段回执，离线后不逐期补跑。脚本不安装定时器；自动化实际启用、运行与上线状态以配置及私有回执为准。旧产品 scheduler 保持停止，普通 `local.ts start` 只启动阅读站点。

| 环节 | 当前约定 |
| --- | --- |
| 来源 | 六条既有来源；保留完整响应、来源失败、缺失与截断 |
| 候选准入 | 新时段采用 `all-in-window`，窗口内符合条件的去重研究全部准入，取消每日 60 条及分来源名额；HF 单列社区信号 |
| 模型处理 | 当天共用 `daily-YYYY-MM-DD` 的 600 次调用硬上限；09 点累计上限 290，15 点累计上限 435，21 点累计上限 580，余下 20 次为报告预留；全局并发 1 |
| 日报 | 已确认成果累计修订，每栏目最多 5 条 |
| 周报 | 周一 09:00 到期，整理上一自然周（ISO 周），每栏目最多 8 条 |
| 月报 | 每月 1 日 09:00 到期，整理上个自然月，每栏目最多 12 条 |
| 原论文配图 | 图文刊物逐条绑定资料 ID 和来源版本；核对原图、图号、说明、作者归属、许可与文件哈希 |
| 成刊 | 只整理现有公开、入选且具备研究解读与合格原图的研究；日周月刊不新增导语模型调用 |
| 发布 | 同一项目锁串行完成成刊、导出、推送及公网核验；公共阶段按持久回执和指数退避自动恢复，直到成功或进入人工 held |

290、435 和 580 均为**当天累计**调用上限。早间剩余额度可在晚间总上限内使用，不能理解为晚间再加 580 次。UNKNOWN 保留已占用次数，重启、修订或更换时段均不清零。全量准入不意味着全量处理或全量刊载；未处理候选、未刊载原因和来源缺口分别留在私有回执中。

arXiv 按官方公告日发现并保存公告证据，但日报准入和刊载只接受原始提交时间落在前一天北京时间 09:00（含）至当天 09:00（不含）的论文；公告日、修订日、社区入选日和本站观测时间不能替代原始提交时间。上午、下午和晚间都使用同一固定刊期窗口，不随实际执行时刻延伸；采集快照时刻单独写入 collection_cutoff。晚间补采来源迟到的资料并继续处理。只有原始发表时间仍在本刊窗口内的身份和已确认结果才能继承，新增研究按原始提交时间优先处理。来源受限、截断、失败与暂未开放保留实际状态，不把它们记成无新研究。

公开阅读页只展示科研内容、原文与图的来源以及科学证据限制；批次 ID、预算、来源运行状态、处理回执和历史补查过程留在本机管理材料。旧试刊不再进入公开导航或静态导出，本机旧 `/pilot` 路径转到日报；原报告和失败证据继续保留。周/月刊使用各自周期内已有的研究材料，缺图或需复核的条目不凑数；无合格材料时不保存空的图文周/月刊。

2026-W40（9 月 28 日至 10 月 4 日）与 2026-09 为本次明确要求补建的历史刊期；是否已生成及上线以本次报告与发布回执确认，不由命令存在推定完成。日常机制仅尝试最新到期周期，不自动循环补齐所有历史刊期。

新时段回执标记 `three-times-daily`；旧 `twice-daily` 和历史三小时回执保留原策略、采集截止和冻结上限。15点是补采与审核时间，不改变科研日期窗口；旧09点回执即使在15点之后才完成，也能按原证据恢复。

2026年10月9日用户明确授权：按原始提交日期重新采集10月5、6、7日三期，额外调度总上限1800次，沿用前一天09:00至当天09:00的刊期，并更新科研动态、日报和热点榜。固定计划为 `recollect-20261009-oct05-07-v1`；每期绑定唯一同名研究批次与600次模型额度，其中研究处理上限580、报告预留20。未用次数不跨期挪用，不要求耗尽额度。日常600次不变。

```bash
# 默认只读状态，不连接数据库或开始任何请求。
node scripts/research-date-backfill.ts --status

# 第一次保存固定计划并重新采集三期；不调用模型。
node scripts/research-date-backfill.ts --run --collect-only

# 在原计划上继续审核、原图核验、日报修订与热点重算。
node scripts/research-date-backfill.ts --run --resume
```

该入口与日常交付共用项目锁。只有三个精确批次ID、冻结的原始提交窗口、已准入且非社区信号的论文，才能使用额外额度；普通日额度与额外额度分开计数，分钟/小时限流和停止开关仍由同一服务锁保护。旧UNKNOWN和failed仍按研究身份隔离；账号错误停止整批，临时服务限流保留断点，不把未完成处理记成已结刊。正文、来源观测、准入、模型提交、处理结果、公开动态和日报条数分别保存。

arXiv使用官方 `submittedDate` API重新采集，保留页码、原始响应及截断；HF按日期补采社区信号；当前RSS不能证明完整历史覆盖。每期报告保留上一修订，并绑定本次批次；整期可复用的已确认成果与本批次处理分母分别记录。全部科研动态不要求具备日报配图，日报仍须有核验合格的原论文图。热点由当前公开投影重新计算；该脚本本身不推送公网，完成后使用原交付回执的 `--refresh-public` 导出、发布并逐文件核验。代码可运行、已开始采集、内容完成和公网更新是不同状态，以实际回执为准。

## 历史刊期与原图复核

日常串联在生成日报后调用 `node scripts/research-editions.ts --due`，仅整理最新到期且尚未成刊的周、月刊，不为导语调用模型。明确补建既有周期可用 `--weekly=2026-W40 --monthly=2026-09`；重复执行复用已保存的图文刊物。

历史材料补充入口为 `scripts/research-backfill.ts`。先用 `--month=2026-09 --calls=140 --collect-only` 保存四段来源窗口，再用相同月份和冻结额度的 `--process-only --stop-at-calls=40` 做有界审核。`40` 是该次执行的共享累计停止线，不是增加40次，也不重置原预算；实际成本仍从当天 `daily-YYYY-MM-DD` 计入。已冻结月份计划后续继续使用同一预算身份。处理队列按真实公告/原始发表日期核对，原始来源观测和准入分母保持不变；历史错误队列必须显式 `--repair-queue`，且仅允许零已处理、零新请求时修复并备份旧计划。

原图缓存保存版本、标题、原图和来源哈希、图注及许可。自动流程仅接纳标题和确切版本匹配、明确方法图注及允许复用的完整单图；其他状态留待复核。PDF 原图可通过 `registerResearchPdfFigureCandidate` 记录页码、完整图框和原PDF哈希，再由 `approveResearchPaperFigure` 对精确图像哈希作视觉确认；不重绘、不把结果曲线当作方法图，也不将许可证据缺失改成通过。核准的本地图自动写入原阅读站的 `public/paper-figures/`，参与静态清单和字节校验。

## 状态、恢复和停止

```bash
# 原时段的完整身份见私有回执。status 不启动服务、采集、模型或发布。
node scripts/daily-delivery.ts --slot 2026-10-08-09 --status
node scripts/daily-delivery.ts --slot 2026-10-08-09 --resume

# 已成刊后仅更新公开样式/材料；不重跑研究模型。
node scripts/daily-delivery.ts --slot 2026-10-08-09 --refresh-public

# 只在需要诊断失效锁时使用；先确认没有活动批次。
node scripts/local.ts status
node scripts/daily-delivery.ts --recover-lock

# 停止指定活动时段；保留数据库与已发布网页。
node scripts/local.ts stop-batch refresh-2026-10-08-09
```

串联回执位于 `.data/daily-delivery/`，来源与模型证据位于数据库及 `.data/research/`，进程证据位于 `.data/local/`。新任务只允许当前到期的09、15或21点时段；旧时段只恢复已经存在的回执及其冻结策略。确认采集错误后的 `--reconcile` 为同一时段建立 `-r1` 修订，保留旧窗口、来源响应、成员与模型回执。修订只继承新固定窗口内的身份，并使用当天累计 580 次上限内的剩余额度，提前使用会减少晚间额度，不退回旧调用、不增加每日 600 次上限；它不是模型失败重试入口。

UNKNOWN 按研究身份隔离，不释放、不重发；其他尚未提交资料继续处理。已知 failed 不因换时段自动重试。pending、真实模型仍在途、登录或账户额度失败阻断后续模型提交。已有项目批次运行时复用其进度，等待其结束，不抢锁或并发启动第二批。暂停后续自动更新应暂停 Codex heartbeat；停止本机进程不会删除已经公开的网页。

公开目标继续为仓库 `PKUCY2016/algorithmhot` 的 `gh-pages` 分支与 `https://pkucy2016.github.io/algorithmhot/`，`main` 保存源码。每次导出对公开字段、原图归属、静态资源和文件清单进行校验；核验同 SHA 的远端分支、Pages 构建与清单内全部公开文件后才记交付成功。导出成功、推送成功和公网核验成功分别留证，不能互相替代。未确认的新快照不会抹去旧失败记录。

报告目录每次读取已提交的数据库元数据，不使用进程内延迟刷新的目录缓存；独立成刊进程新增日、周或月刊后，下一次目录请求即可包含新刊。导出仍校验每个阅读链接是否属于本次快照；出现目录与页面链接不一致时保留失败，不绕过校验发布。

#### 每 3 小时日内刷新（2026-10-05 起）

已在2026-10-05核对 heartbeat `algorithmhot` 为 ACTIVE，通知策略沿用仅失败提醒。当前定时入口改为：

```bash
node scripts/daily-delivery.ts --refresh

```

北京时间每 3 小时运行（00、03、06、09、12、15、18、21 点），每次新时段重新获取六条来源，并将新增研究累计到当天日报。首次触发冻结实际截至时刻；同一时段的再次触发复用回执，不重复调用模型。页面显示实际来源窗口与“日内更新”。旧版固定 08:00 的默认入口仍保留作手动兼容入口，heartbeat 不再使用它。

每次来源观测使用不可变 `refresh-YYYY-MM-DD-HH` 快照；当天全部刷新共用 `daily-YYYY-MM-DD` 的 **600 次模型调用**预算与 **60 条去重准入**名额，包含当天已有08:00批次。已准入条目、判断与错误继承；来源响应和旧报告修订保留。来源窗口从前一天08:00延伸到本次实际截至时刻，便于补上此前来源不可用及延迟收录的记录。通过既有回执复用相同内容，不用新时段重发 UNKNOWN。

脚本串联与旧版共用项目锁。任何一天新快照都不会突破当天预算。若存在 pending 请求或真实模型执行仍在途，停止新生成，保留原站点。UNKNOWN 按研究身份隔离，不释放、不重发、不退回已占用次数；其他尚未提交的资料继续在原准入和预算内处理。账户、登录或额度失败仍停止后续模型请求。来源失败保留 PARTIAL，不能称为“今日无新研究”。已知失败模型条目不因换时段自动重试。

定时触发时若已有该项目批次运行，应读取并复用其进度，等待该批次完成；不重启服务、不回收活动锁、不另起并行批次。

arXiv 刷新以官方 `recent` 列表的公告日期发现论文，再按确切 ID 获取原始摘要和元数据；不能用 API `submittedDate` 代替公告日期。公告日和原始提交时间分别保存并显示，早先提交、今天公告的论文仍可进入当天处理。列表分页和原始响应留存；元数据缺失或截断保留来源缺口。HF 入选日期仍只是独立的热度信号。

当 API 达到有界重试上限，当前批次停止继续请求该 API，改从官方 `new` 公告网页的明确摘要段获取同一公告 ID 集合的材料。原提交时间在该页缺失时保留未知；不以公告日期代替。网页包含的修订等集合外记录单列排除数量，不能记为重复或解析失败。发现 ID、取得摘要 ID、缺失 ID 和原始失败都保存在私有回执中，后续补齐不抹去上游失败。

若已完成快照因已确认的采集错误需要纠正，可显式执行一次 `--slot YYYY-MM-DD-HH --reconcile`，产生同一时段的 `-r1` 修订，要求原快照已经冻结；修订沿用当天 60 条准入与 600 次调用额度。它不是失败请求自动重试入口，定时任务也不使用该参数。恢复时必须使用完整的 `--slot YYYY-MM-DD-HH-r1 --resume`。当天旧报告和旧采集回执保留。

静态站的“全部动态”分页来自公开资料池，包含通过筛选的非精选条目；首页和主题页保留精选范围。网页更新时间只表示导出时间，不能当成论文的公告或提交时间。

每次发布由 `verify` 阶段自动核对远端提交、同 SHA 的 Pages 构建，以及公开清单内的全部文件（包含 `/all/` 所有分页、精选、热点、主题和日报）。执行代理仍核对新公告、已处理与未准入的完整分母。交付说明分别报告已处理、已上线与未准入数量；抓取成功不等于新内容已上线。

产刊默认采用 `composePilot(runId, true, { ruleOnly: true })` 整理已确认结果：只采用主流程通过、公开可用且已有研究解读的精选条目，使用确定性规则导语，不再新增报告导语模型请求。研究筛选与解读仍由原模型流程完成。报告保留共享预算的未知请求、已隔离条目、未处理资料和来源缺口；旧失败串联回执不改写为成功。隔离继续处理与成刊分别核对新增调用和刊载数量。

失败恢复须使用回执上的完整时段，而不是换新ID，例如：

```bash
node scripts/daily-delivery.ts --slot 2026-10-05-09 --status
node scripts/daily-delivery.ts --slot 2026-10-05-09 --resume
```

`--refresh` 已将成刊后的导出、发布和公网核验恢复固定到程序：自动与手动 `--resume` 共享同一持久回执；明确暂态错误按指数退避继续，恢复前核对活动进程、模型锁、pending 与原报告修订。失败证据保留，不再依赖人工输入恢复命令。主动中断不会当场自动重试。新模型提交成为 UNKNOWN 时立即记录隔离，保留原回执，继续其他尚未提交的资料；不能因此创建重试请求。Mac 需开机、联网且 Codex 可调度；睡眠/离线期间不会追跑所有错过时段。当前时段完成情况见私有 `.data/daily-delivery/` 回执与公网交付记录。

#### 旧版每日入口（手动兼容）

在项目 `app/` 目录执行：

```bash
node scripts/daily-delivery.ts
```

默认按执行时刻选择**最近已关闭的北京时间 09:00 刊期**。例如 10 月 4 日 09:00 后执行，处理 10 月 3 日 09:00 至 10 月 4 日 09:00；10 月 4 日 08:59 执行仍选择 10 月 3 日刊期。长时间关机后，只处理最近一期，不循环补发历史日报。

执行顺序为：专用数据库就绪 → 本地网页/API 就绪 → 日报生成 → 公共静态导出 → GitHub 发布 → 公网核验。未成功的阶段阻止后续步骤；符合条件的公共阶段按持久回执执行有界自动恢复并指数退避；校验、安全、凭证或未知错误进入 held。采集失败、模型额度不足或结果未知造成的 `partial` 报告可以发布，但保持原有缺口提示，不能称为“今日无研究”。健康空刊是有效报告。

脚本默认使用以下公开位置：

- 仓库：`PKUCY2016/algorithmhot`
- 源码分支：`main`；网页发布分支：`gh-pages`。不再同步到另一个源码仓库。

#### 调度方式

当前 Codex heartbeat 使用上面的每3小时日内入口；以下为旧版固定日报入口的行为。脚本本身不安装定时器，不创建 `launchd` 项，也不常驻运行。Codex 应用/本机需要具备执行条件；账户额度、登录和上游网络仍可能阻止当日更新。没有运行记录就不能认为已经持续运行。

原有产品 scheduler 保持停止，避免两个自动生产者并行。启动网页不代表启动采集、模型或定时器。首次接入须另行确认 heartbeat 已配置成功；仅存在本文件并不意味着已启用自动更新。

每期使用稳定的 `daily-YYYY-MM-DD` 批次身份，沿用已有冻结准入与持久模型预算，每批最多 60 条候选、600 次应用模型调用。重复触发已完成的一天不会再次生成、导出或发布。模型全局并发及回执规则仍由既有处理层执行。

#### 状态与恢复

```bash
# 只读查看最近到期刊期与串联回执，不启动服务、模型或发布。
node scripts/daily-delivery.ts --status

# 查看指定日期。
node scripts/daily-delivery.ts --date 2026-10-04 --status

# 先核对私有日志和回执，再明确恢复同一日期。
node scripts/daily-delivery.ts --date 2026-10-04 --resume

# 已成刊后更新样式/公开材料，仅重新导出和发布，不重新调用模型产刊。
node scripts/daily-delivery.ts --date 2026-10-04 --refresh-public
```

串联回执和分阶段日志保存在 `.data/daily-delivery/`，来源与模型回执仍保存在既有数据库及 `.data/research/daily-YYYY-MM-DD/`。这些文件不发布至 GitHub。

旧版每日入口遇到未完成串联仍需明确 `--resume`；当前 `--refresh` 自动恢复符合条件的公共阶段一次。成功产刊阶段始终复用；导出成功、发布失败时，只继续未完成的公共阶段，不重启阅读服务、不重复模型处理。若进程在保存串联回执前已成刊，会通过数据库识别同一期既有报告并复用。不会自动调用 `revise`，也不会另造批次 ID。

产刊前只读核对模型执行锁与 pending 请求。有请求仍在途或 pending 尚未结束时停止；已有 `UNKNOWN` 回执按研究身份隔离、不释放、不重发，处理层保留其缺口，并继续其他尚未提交资料。登录失效或额度用完时保留状态，待账户条件恢复后人工/代理核对回执，再显式恢复。

单一项目锁同时保护当日生产和共享导出目录。异常退出留下锁时，先确认项目没有活动批次：

```bash
node scripts/local.ts status
node scripts/daily-delivery.ts --recover-lock
```

只有锁属主进程已死亡，且没有项目 batch/scheduler 活动时才归档旧锁；不杀死进程抢锁。此命令不会生成或发布。随后仍需查看回执并使用原日期 `--resume`。

#### 停止

暂停每日更新应暂停 Codex heartbeat。若当日批次正在执行，使用其确定 ID 停止：

```bash
node scripts/local.ts stop-batch daily-2026-10-04
```

这会保留网页、API、数据库及既有公网快照。需要关闭本机整个项目时使用 `node scripts/local.ts stop-all`；数据和公网已发布内容仍保留。
