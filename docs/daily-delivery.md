# 每日自动产刊与公网更新

本机承担采集、Codex 模型处理和报告生成，GitHub Pages 仅提供公开阅读快照。Mac 关机或断网时，已发布的网页继续可读；新增报告要等本机有执行机会。使用现有 Codex 登录，不新增托管服务，不自动切换账号或付费 API。

## 每 3 小时日内刷新（2026-10-05 起）

已在2026-10-05核对 heartbeat `algorithmhot` 为 ACTIVE，通知策略沿用仅失败提醒。当前定时入口改为：

```bash
node scripts/daily-delivery.ts --refresh
node scripts/daily-delivery.ts --refresh --status
```

北京时间每 3 小时运行（00、03、06、09、12、15、18、21 点），每次新时段重新获取六条来源，并将新增研究累计到当天日报。首次触发冻结实际截至时刻；同一时段的再次触发复用回执，不重复调用模型。页面显示实际来源窗口与“日内更新”。旧版固定 08:00 的默认入口仍保留作手动兼容入口，heartbeat 不再使用它。

每次来源观测使用不可变 `refresh-YYYY-MM-DD-HH` 快照；当天全部刷新共用 `daily-YYYY-MM-DD` 的 **600 次模型调用**预算与 **60 条去重准入**名额，包含当天已有08:00批次。已准入条目、判断与错误继承；来源响应和旧报告修订保留。来源窗口从前一天08:00延伸到本次实际截至时刻，便于补上此前来源不可用及延迟收录的记录。通过既有回执复用相同内容，不用新时段重发 UNKNOWN。

脚本串联与旧版共用项目锁。任何一天新快照都不会突破当天预算。若存在 pending 请求或真实模型执行仍在途，停止新生成，保留原站点。UNKNOWN 按研究身份隔离，不释放、不重发、不退回已占用次数；其他尚未提交的资料继续在原准入和预算内处理。账户、登录或额度失败仍停止后续模型请求。来源失败保留 PARTIAL，不能称为“今日无新研究”。已知失败模型条目不因换时段自动重试。

定时触发时若已有该项目批次运行，应读取并复用其进度，等待该批次完成；不重启服务、不回收活动锁、不另起并行批次。

arXiv 刷新以官方 `recent` 列表的公告日期发现论文，再按确切 ID 获取原始摘要和元数据；不能用 API `submittedDate` 代替公告日期。公告日和原始提交时间分别保存并显示，早先提交、今天公告的论文仍可进入当天处理。列表分页和原始响应留存；元数据缺失或截断保留来源缺口。HF 入选日期仍只是独立的热度信号。

当 API 达到有界重试上限，当前批次停止继续请求该 API，改从官方 `new` 公告网页的明确摘要段获取同一公告 ID 集合的材料。原提交时间在该页缺失时保留未知；不以公告日期代替。网页包含的修订等集合外记录单列排除数量，不能记为重复或解析失败。发现 ID、取得摘要 ID、缺失 ID 和原始失败都保存在私有回执中，后续补齐不抹去上游失败。

若已完成快照因已确认的采集错误需要纠正，可显式执行一次 `--slot YYYY-MM-DD-HH --reconcile`，产生同一时段的 `-r1` 修订，要求原快照已经冻结；修订沿用当天 60 条准入与 600 次调用额度。它不是失败请求自动重试入口，定时任务也不使用该参数。恢复时必须使用完整的 `--slot YYYY-MM-DD-HH-r1 --resume`。当天旧报告和旧采集回执保留。

静态站的“全部动态”分页来自公开资料池，包含通过筛选的非精选条目；首页和主题页保留精选范围。网页更新时间只表示导出时间，不能当成论文的公告或提交时间。

每次发布须核对公网 `/all/` 新公告条目、公开资料池总数和分页，以及精选和日报各自范围。交付说明分别报告已处理、已上线与未准入数量；抓取成功不等于新内容已上线。

产刊默认采用 `composePilot(runId, true, { ruleOnly: true })` 整理已确认结果：只采用主流程通过、公开可用且已有研究解读的精选条目，使用确定性规则导语，不再新增报告导语模型请求。研究筛选与解读仍由原模型流程完成。报告保留共享预算的未知请求、已隔离条目、未处理资料和来源缺口；旧失败串联回执不改写为成功。隔离继续处理与成刊分别核对新增调用和刊载数量。

失败恢复须使用回执上的完整时段，而不是换新ID，例如：

```bash
node scripts/daily-delivery.ts --slot 2026-10-05-09 --status
node scripts/daily-delivery.ts --slot 2026-10-05-09 --resume
```

仅已成刊后的导出/发布允许最多一次恢复。新模型提交成为 UNKNOWN 时立即记录隔离，保留原回执，继续其他尚未提交的资料；不能因此创建重试请求。Mac 需开机、联网且 Codex 可调度；睡眠/离线期间不会追跑所有错过时段。当前时段完成情况见私有 `.data/daily-delivery/` 回执与公网交付记录。

## 旧版每日入口（手动兼容）

在项目 `app/` 目录执行：

```bash
node scripts/daily-delivery.ts
```

默认按执行时刻选择**最近已关闭的北京时间 08:00 刊期**。例如 10 月 4 日 08:00 后执行，处理 10 月 3 日 08:00 至 10 月 4 日 08:00；10 月 4 日 07:59 执行仍选择 10 月 3 日刊期。长时间关机后，只处理最近一期，不循环补发历史日报。

执行顺序为：专用数据库就绪 → 本地网页/API 就绪 → 日报生成 → 公共静态导出 → GitHub 发布。任何阶段失败都会停止后续步骤。采集失败、模型额度不足或结果未知造成的 `partial` 报告可以发布，但保持原有缺口提示，不能称为“今日无研究”。健康空刊是有效报告。

脚本默认使用以下公开位置：

- 仓库：`PKUCY2016/algorithmhot`
- 源码分支：`main`；网页发布分支：`gh-pages`。不再同步到另一个源码仓库。
- 网站：`https://pkucy2016.github.io/algorithmhot/`
- 静态导出目录：`.data/public-site`

`STATIC_SITE_REPO` 和 `STATIC_SITE_BASE` 可用于明确指定另一 GitHub Pages 项目地址，二者必须匹配。每期目标地址在回执里冻结；恢复同一期不能悄悄换仓库。导出从项目 `.env` 中读取 `SITE_URL`，仅接受无凭据的本机 HTTP 地址；不会将 `.env` 复制至公开文件。

## 调度方式

当前 Codex heartbeat 使用上面的每3小时日内入口；以下为旧版固定日报入口的行为。脚本本身不安装定时器，不创建 `launchd` 项，也不常驻运行。Codex 应用/本机需要具备执行条件；账户额度、登录和上游网络仍可能阻止当日更新。没有运行记录就不能认为已经持续运行。

原有产品 scheduler 保持停止，避免两个自动生产者并行。启动网页不代表启动采集、模型或定时器。首次接入须另行确认 heartbeat 已配置成功；仅存在本文件并不意味着已启用自动更新。

每期使用稳定的 `daily-YYYY-MM-DD` 批次身份，沿用已有冻结准入与持久模型预算，每批最多 60 条候选、600 次应用模型调用。重复触发已完成的一天不会再次生成、导出或发布。模型全局并发及回执规则仍由既有处理层执行。

## 状态与恢复

```bash
# 只读查看最近到期刊期与串联回执，不启动服务、模型或发布。
node scripts/daily-delivery.ts --status

# 查看指定日期。
node scripts/daily-delivery.ts --date 2026-10-04 --status

# 先核对私有日志和回执，再明确恢复同一日期。
node scripts/daily-delivery.ts --date 2026-10-04 --resume

# 已成刊后更新样式/公开材料，仅重新导出和发布，不重新调用模型产刊。
node scripts/daily-delivery.ts --date 2026-10-04 --refresh-public
```

串联回执和分阶段日志保存在 `.data/daily-delivery/`，来源与模型回执仍保存在既有数据库及 `.data/research/daily-YYYY-MM-DD/`。这些文件不发布至 GitHub。

默认触发遇到未完成串联会停下，不自动重复模型处理。明确 `--resume` 后，成功产刊阶段会复用；导出成功、发布失败时，只重试发布，并重新确认本地服务可用。若进程在保存串联回执前已成刊，会通过数据库识别同一期既有报告并复用。不会自动调用 `revise`，也不会另造批次 ID。

产刊前只读核对模型执行锁与 pending 请求。有请求仍在途或 pending 尚未结束时停止；已有 `UNKNOWN` 回执按研究身份隔离、不释放、不重发，处理层保留其缺口，并继续其他尚未提交资料。登录失效或额度用完时保留状态，待账户条件恢复后人工/代理核对回执，再显式恢复。

单一项目锁同时保护当日生产和共享导出目录。异常退出留下锁时，先确认项目没有活动批次：

```bash
node scripts/local.ts status
node scripts/daily-delivery.ts --recover-lock
```

只有锁属主进程已死亡，且没有项目 batch/scheduler 活动时才归档旧锁；不杀死进程抢锁。此命令不会生成或发布。随后仍需查看回执并使用原日期 `--resume`。

## 停止

暂停每日更新应暂停 Codex heartbeat。若当日批次正在执行，使用其确定 ID 停止：

```bash
node scripts/local.ts stop-batch daily-2026-10-04
```

这会保留网页、API、数据库及既有公网快照。需要关闭本机整个项目时使用 `node scripts/local.ts stop-all`；数据和公网已发布内容仍保留。
