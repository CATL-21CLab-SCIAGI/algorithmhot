GitHub 上 AI 智能体的合并请求研究：并行频率、结构与合并冲突率

AI Agent Pull Requests on GitHub: Frequency, Structure, and Merge Conflict Rates

AI 导读

该研究报告，GitHub 上不同 AI 智能体的并行 PR 在合并回放中的文本冲突率高于同一智能体的并行 PR。

基于摘要arXiv:2607.04697v2
研究变化
作者报告了一项关于 AI 编程代理向同一代码仓库并发提交 Pull Request（PR）的实证研究，旨在量化并发提交的普遍程度及其文本合并冲突风险，而非提出新的编程代理或冲突修复算法。研究分别采用精确时间重叠和一周协作窗口识别共活跃 PR，比较同一代理与不同代理所作 PR 的共活跃情况；随后重放实际三方 git 合并，并基于 git 报告的冲突建立分类体系。作者将其称为首次针对代理所作 PR 并发提交普遍程度的实证考察；这一首创性表述仅为作者报告。
适用任务
资料支持的研究任务包括：统计同一仓库内 AI 代理所作 PR 的共活跃程度，比较同一代理与不同代理 PR 对的文本合并冲突发生率，以及按受影响文件类型和结构性冲突类型分析冲突。研究对象为 AIDev-pop 数据集中的代理所作 PR，观察范围为其中的 2,807 个仓库、33,596 个 PR。适用的时间口径包括精确时间重叠及一周协作窗口。对其他数据集、人类提交的 PR、语义冲突或自动修复效果的适用性，未知：当前资料未提供。
作者报告的比较条件
作者使用 AIDev-pop 数据集，共 33,596 个 PR、2,807 个仓库。按精确时间重叠口径，40.2% 的仓库含共活跃的代理 PR 对，共活跃 PR 对涉及的 PR 占全部 AI 代理生成 PR 的 79.4%；按一周协作窗口口径，上述两个比例分别为 53.4% 和 95.0%。这些指标分别以仓库数和代理生成的 PR 数为分母，不能互换。作者报告多数共活跃 PR 对由同一代理撰写，跨代理对仅占共活跃 PR 对的 0.5%，出现在全部 2,807 个仓库中的 122 个，约占 4.3%；摘要未明确这些跨代理统计对应哪一种时间窗口。作者另对 747 个唯一共活跃 PR 对重放实际三方 git 合并，每个仓库取一对；跨代理对与同一代理对的文本合并冲突发生率分别为 41.7% 和 19.8%，作者报告前者显著更高，两组 95% 置信区间不重叠。摘要未给出两组各自的样本数、置信区间端点及显著性检验细节。冲突分类中，源代码文件占发生冲突文件的 84.4%，作者据此指出多数冲突涉及源代码文件而非依赖清单文件；观察到的冲突中近 42% 为结构性冲突，即 modify/delete 或 add/add。代理及模型的名称与数量、独立任务数量、硬件、计算资源、git 版本、合并参数与耗时均未知：当前资料未提供。
证据限制
当前证据仅为摘要，未核对全文；所有比例、冲突分类及显著性结论均为作者报告，当前资料不构成独立复现。总体观察基于一个给定数据集，合并重放仅涉及 747 个唯一共活跃 PR 对、每仓库一对，不能直接视为对全部 33,596 个 PR 或所有共活跃 PR 对逐一合并验证。摘要未提供数据采集时段、代理身份判定方法、时间重叠的操作定义、重放样本筛选细节、两类代理对样本构成或分类验证流程，也未说明近 42% 结构性冲突比例的具体计数单位。文本合并冲突结果不足以证明语义正确性、功能质量、实际协作效率或因果关系。作者明确陈述的研究限制、代码与数据开放情况、独立复现及其他数据集验证信息均未知：当前资料未提供。
