UndoBench：区分工具调用 AI 智能体的任务能力与故障恢复能力

UndoBench: Separating Task Competence from Recovery Capability in Tool-Using AI Agents

AI 导读

UndoBench 提出用反事实配对试验区分工具调用 AI 智能体的任务能力与故障恢复能力，作者报告两者存在明显差距。根据当前材料，该基准覆盖 8 个企业领域的 36 个基础工作流与 36 种故障场景，采用相同随机种子，并结合通信层面的效应历史与环境状态判定。

基于摘要arXiv:2610.05622v1
研究变化
作者提出 UndoBench 基准，以解决现有基准主要评估正常条件下的任务完成、将基础规划能力与运行故障恢复能力混为一谈的问题。其方法是在相同随机种子下开展反事实配对试验，并结合通信层面的效应历史与环境状态判定器（oracles），分离任务能力和恢复能力。作者还通过不同执行阶段的故障评估，考察恢复能力与故障发生阶段的关系。
适用任务
资料支持的评估对象是企业软件系统中使用工具的 AI 智能体，任务涉及正常工作流完成、运行故障恢复及重复外部效应等安全问题。UndoBench 覆盖 8 个企业领域、36 个基础工作流和 36 种故障场景；摘要未说明工作流与故障场景是否全组合。冻结的确认丢失研究使用其中 12 个留出的 TEST 工作流。补充评估涉及状态变更前、部分状态变更期间，以及提交完成但确认尚未收到三个执行阶段；部分状态变更阶段的结论限定于所评估的复合工作流。具体企业领域、工作流及故障场景清单未知。
作者报告的比较条件
作者报告：冻结的确认丢失研究覆盖 12 个留出的 TEST 工作流、2 个开放权重模型、2 个框架和 3 种恢复范式，共 5,760 次执行／2,880 组配对试验；配对试验使用相同随机种子。正常条件下的任务能力达到 83.54%，条件恢复成功率（CRSR）降至 46.72%；朴素重试在 53.33% 的试验中产生重复外部效应。上述指标单位均为百分比，摘要未说明其平均、最高或其他聚合口径，也未给出各比例的完整分母定义和具体样本数，不能直接将总执行数或总配对数视为各指标分母。作者还报告，将评估扩展至商业 API 模型后，再次观察到任务能力与恢复能力的分离，但未给出商业模型名称、数量及数值结果。不同执行阶段的比较结果为：状态变更前，各方法表现相近，在具备任务完成能力的试验中未出现重复效应；部分状态变更期间，朴素重试、逐调用幂等性和零特权日志记录在所评估的复合工作流上均失效；提交完成但确认尚未收到时，验证与服务端幂等性显著改善安全性。摘要未给出这些阶段比较的具体效应量、试验数量或统计检验，亦未明确其与前述 3 种恢复范式的对应关系。模型与框架名称、硬件、计算资源、推理参数、随机种子取值、成本及耗时未知：当前资料未提供。
证据限制
当前证据仅为摘要，未核对全文；所有结果均为作者报告，未提供独立复现证据。商业 API 模型扩展中再次观察到相同现象，属于作者报告的扩展验证，不能视为独立复现。作者强调，仅评估正常任务完成会掩盖关键的、依赖执行阶段的恢复漏洞；摘要中的阶段性结果不能推广为某种方法在全部故障、工作流或模型上普遍有效或无效。摘要未提供完整实验协议、CRSR 的严格定义、各条件样本分配、分项结果、不确定性估计、显著性检验或更广泛部署验证；也未提供代码、数据或开放实现的可用性证据。除所述评估范围及阶段依赖性外，作者是否在全文中陈述其他限制未知；上述信息缺失仅指当前资料未提供，不能据此断言研究本身不存在相应内容。
