Oracle 计算研究提出统一描述 Agent 与 Workflow 的抽象机

We Query, Therefore We Compute: On Oracle Computation beyond the Machine, with an Application to Agents

AI 导读

根据当前材料，该研究提出将 LLM 视为 Oracle 的抽象机，以统一描述 Agent 与 Workflow。该模型为双栈下推自动机增加整栈查询指令，将 Oracle 计算与图灵完备的 Priestess 计算结合，并通过任务程序的位置区分智能体与工作流。

基于摘要arXiv:2610.09243v1
研究变化
作者针对既有智能体系统零散借用操作系统的调度、缓存、隔离等抽象，导致机制缺少共同基础、对 Agent 与 Workflow 缺乏统一认识的问题，构建统一抽象机。该方法将 LLM 视为 Oracle，在双栈下推自动机上增加一条指令：把一个完整栈交给 Oracle 作为查询，再将回答追加到同一栈。机器由此包含 Oracle 的计算和作者称为 Priestess 的图灵完备计算；程序仅追加内容的栈呈自回归增长，对应智能体上下文的增长。作者通过存储上的 S 和状态转移上的 T 两种对称性破缺，使 Priestess 程序成为 Oracle 所运行程序的操作系统，并把 Agent 与 Workflow 解释为任务程序的两种放置方式。在一定条件下，内部自回归 Oracle 的两种计算会在每次回答结束时同步，作者据此建模缓存并分析调度。构造 V 将抽象机适配到冯·诺依曼计算机；作者进一步提出扩展 RISC-V 指令集架构及 Linux 风格操作系统 ArchNights，以展示该抽象机的可实现性。
适用任务
资料支持的范围是：为使用 LLM 执行具体任务的智能体系统提供统一的计算与系统设计基础，涵盖 Agent 和 Workflow 两种形式，以及缓存建模、调度分析和抽象机到计算机系统的实现。回答结束时的同步分析限定于内部自回归的 Oracle，且需要满足摘要未展开的条件。作者报告 ArchNights-SE 在 gem5 上作为计算机系统运行，并在使用 LLM 作为 Oracle 时成为智能体系统。具体应用领域、任务实例、数据类型、LLM 型号及经验证的适用规模未知：当前资料未提供。
作者报告的比较条件
比较背景是既有工作对操作系统抽象的零散借用；摘要未列出具体比较系统、基线或定量对照实验。数据集、模型和任务的名称与数量均未知。明确给出的架构与运行环境是扩展 RISC-V 指令集架构、Linux 风格操作系统，以及 ArchNights-SE 在 gem5 上运行；物理硬件、模拟处理器配置、内存、加速器、LLM 推理配置、并发规模和计算预算均未知。作者报告的结果是统一抽象机的构建、带条件的同步及缓存和调度分析，以及所述系统实现；摘要未提供性能或质量指标、单位、测量值、最高或平均增益、统计分母及不同实验条件下的结果，因此不能据此量化相对既有系统的收益。
证据限制
证据仅为当前提供的摘要，未核对全文。作者明确将内部自回归 Oracle 的回答结束同步限定在一定条件下，但摘要未给出这些条件或证明细节。作者还指出，对每个 Oracle 都成立的保证无法固定两种计算之间传递的具体内容，但能够固定边界本身；这一陈述不能扩展为对传递内容或任务输出质量的普遍保证。ArchNights-SE 的运行与可实现性属于作者报告，当前资料未提供独立复现、具体任务评测、性能测量或真实硬件验证信息。摘要称系统将开源，这是未来计划，不能据此认定当前已有可获取代码或可复现环境。作者将共享附带条件的不变量与界限作为未来工作的方向；摘要不足以确认其在具体任务上的效果或广泛适用性。
